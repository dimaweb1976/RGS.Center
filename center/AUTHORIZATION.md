# Авторизация RGSCenter

Авторизация использует модель из `Docs/rgscenter_tables.docx`:

- `roles(id, rolename)` — справочник ролей;
- `users(id, login, hash, role)` — пользователи, где `role` ссылается на
  `roles.id`, а `hash` содержит BCrypt-хэш пароля;
- `auth_sessions` — техническая таблица серверных токен-сессий, связанная с
  `users.id`.

Предустановлены роли `service`, `administrator`, `operator` и одноимённые
пользователи `service`, `admin`, `operator`. Их начальные пароли совпадают с
логинами, поэтому после первого развёртывания пароли необходимо сменить.

## Роли в Java

При успешной проверке пароля имя роли загружается через `users JOIN roles` и
добавляется в Spring Security в формате:

- `service` → `ROLE_SERVICE`;
- `administrator` → `ROLE_ADMINISTRATOR`;
- `operator` → `ROLE_OPERATOR`.

Текущая конфигурация требует аутентификацию для защищённых страниц. Полученные
authorities готовы для последующего разграничения доступа через `hasRole(...)`
или аннотации Spring Security.

## Токены и подключения

- Браузер получает случайный 256-битный токен в cookie `RGS_AUTH_TOKEN`.
- Cookie имеет флаги `HttpOnly`, `SameSite=Strict` и путь `/`.
- В базе хранится только SHA-256-хэш токена; сырой токен нельзя восстановить.
- Токен действует 8 часов и немедленно отзывается при выходе.
- Подключённым считается браузер, проявлявший активность за последние 90 секунд.
- Интерфейс опрашивает счётчик каждые 30 секунд и показывает предупреждение,
  когда одновременно подключено больше одного браузера.

## Настройки окружения

Подключение к БД можно переопределить переменными `RGSCENTER_DB_URL`,
`RGSCENTER_DB_USER`, `RGSCENTER_DB_PASSWORD`. При работе через HTTPS обязательно
установить `RGSCENTER_COOKIE_SECURE=true`.

Схема создаётся идемпотентным файлом `src/main/resources/schema.sql` при запуске
приложения. Скрипты чистого развёртывания и переноса старой `appusers` находятся
в каталоге `dbscripts`.
